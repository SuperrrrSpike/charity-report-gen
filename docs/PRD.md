# Charity Compliance Report Generator — PRD

> 个人原型项目 / vibe coding demo，用于腾讯公益平台·产品实习生岗位投递。
> 目标：在 5–8 天内交付一个可在线体验的 MVP，覆盖"公益机构上传项目素材 → AI 生成合规报告 + 捐赠人公示页"的完整闭环。

---

## 1. 一句话定位

**让中小型公益机构 5 分钟生成一份符合慈善法信息披露要求的项目报告 + 捐赠人友好的公示页。**

## 2. 目标用户

### 2.1 B 端：公益机构项目官员
- 痛点：年度合规报告格式严、手工整理耗时长；缺数字化能力的小机构常因不合规被驳回
- 场景：项目结项 / 年报 / 重大事件披露
- 期望："上传原始素材 → 自动生成结构化报告 → 导出 PDF / 捐赠人公示页"

### 2.2 C 端：捐赠人 / 社会公众
- 痛点：捐赠后看不到钱去了哪里；机构公示页风格不一、阅读门槛高
- 场景：捐赠回访、项目溯源、向亲友分享
- 期望："扫码 / 点链接 → 看到资金流向 + 受益人故事 + 财务关键数字"

### 2.3 监管 / 平台方（次级）
- 一键导出监管表格版（结构化 JSON / Excel），便于平台/民政系统接入

## 3. 核心场景（用户故事）

**US-1：B 端生成合规报告**
> 作为机构项目官员，我希望上传一份项目结项材料（项目描述 + 财务表 + 受益人反馈），系统自动生成一份符合慈善法信息披露要求的标准报告（包含：项目概况、收支明细、捐赠人构成、受益人故事、合规声明），并支持导出 PDF。

**US-2：C 端看公示页**
> 作为捐赠人，我希望通过分享链接看到该项目的资金流向、关键数字和受益人故事，而不是一堆看不懂的财务表格。

**US-3：多端分发**
> 作为机构，我希望同一份内容自动适配网页 / 移动端 / 邮件摘要三种形式，链接可直接发到微信公众号。

## 4. 功能清单（MVP 范围）

### 4.1 必做（MVP 核心）
- [ ] 项目素材上传（粘贴文本 / 上传 Markdown / JSON 三选一）
- [ ] AI 结构化提取（项目名 / 时间 / 金额 / 受益人 / 关键事件 / 财务表）
- [ ] 合规报告渲染（标准版 + 捐赠人友好版双版本同屏对照）
- [ ] 一键导出 Markdown / HTML 片段，可贴入公众号 / 邮件
- [ ] 监管表格版导出（JSON Schema，可被后续系统解析）
- [ ] 演示用 mock 数据：3 个真实风格的公益项目案例（"乡村图书馆 / 重疾患儿救助 / 灾后应急"）

### 4.2 加分（时间允许再补）
- [ ] LLM Provider 切换（OpenAI / Anthropic / 本地 Ollama）
- [ ] 历史项目对比 / 多项目仪表盘
- [ ] 链接分享 + 简单访问统计（用 Supabase 存储）
- [ ] AI 风险提示（检测金额异常 / 时间线错位 / 受益人数对不上）

## 5. 技术栈（轻量 + 国内可访问）

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | 单页 HTML + Tailwind CDN + Font Awesome | 复用 fitness-coach-agent 同栈；CDN 国内可访问 |
| 数据 | 浏览器 LocalStorage + 可选 Supabase | MVP 阶段不上后端也能演示 |
| AI | Claude / GPT / 本地 Ollama 三选一（环境变量切换） | 演示 vibe coding 灵活度 |
| 部署 | Netlify / Vercel | 复用现有配置 |
| PDF 导出 | 浏览器 `window.print()` 或 html2pdf.js | 不引入重依赖 |
| 测试 | Playwright 跑 3 个 mock 案例 | 复用固定收益项目经验 |

## 6. 信息架构（页面）

```
/                → 首页（3 个 mock 案例卡片）
/demo/<slug>     → 案例详情（已生成报告 + 切换 B/C 端视图）
/generate        → B 端生成入口（上传素材 → AI 提取 → 报告预览）
/generate/done   → 报告完成（导出 + 分享）
```

## 7. 演示数据：3 个 mock 案例

| 案例 | 主题 | 关键数字 | 故事角度 |
|---|---|---|---|
| 星火图书馆 | 乡村儿童阅读 | 资助 12 县、72 馆、受益学生 18,500 人 | 教育公平 |
| 重疾患儿救助 | 0–14 岁医疗救助 | 资助 234 例、覆盖 21 省 | 生命救助 |
| 暴雨应急响应 | 灾后 72h 救援 | 救援队 6 支、转移群众 1,200 人 | 应急响应 |

每个案例预置：
- 一段项目描述（200–300 字）
- 一张收支表（JSON 格式）
- 3 段受益人反馈
- 一份预生成的标准报告（让 demo 即开即看，不用等 LLM）

## 8. vibe coding 价值体现（面试主线）

1. **AI 加速 PRD→原型**：从 PRD 到单页 Web，用 Cursor 半天交付
2. **AI 加速数据准备**：3 个 mock 案例的财务表 + 受益人反馈，用 AI 半天生成
3. **AI 加速报告生成**：核心 prompt + JSON schema 在 1 天内调通
4. **人工评审关键节点**：所有 AI 生成的财务数字必须 mock 数据对齐，关键文案人工复核（与 china-fixed-income-lab 一致的 LLM 边界处理原则）

## 10. 风险与边界

- **AI 不能做**：财务数字生成（必须来自机构原始数据）；合规签字（必须机构法人确认）
- **AI 适合做**：文案润色 / 结构化提取 / 跨格式改写 / 风险字段初筛
- **隐私**：mock 数据为虚构；真实数据接入需先做脱敏 + 审计日志
- **不写**：金融系统 / 平台架构师 / 真实生产部署 / 客户名单
